# 皮肤切换器-Skin Changer

一个独立的《杀戮尖塔 2》皮肤管理 Mod。它不会修改其他 Mod，也不依赖旧版“皮肤管理器”。

当前同时兼容正式版 `v0.107.1` 与公开测试版 `v0.111.0`；发布 DLL 以最低支持版本 `v0.107.1` 构建。

[Steam 创意工坊 / Steam Workshop](https://steamcommunity.com/sharedfiles/filedetails/?id=3787302680)

## 功能

- 自动识别已加载、且 `affects_gameplay=false` 的纯外观 PCK，以及通过 DLL 接管原场景的外观 Mod。
- 按角色、远古者以及怪物分别归类皮肤。
- 每一组都可切回游戏原版或当前玩法 Mod 提供的基础外观。
- 在选角界面切换当前角色的皮肤。
- 选角界面严格按需打包当前预览的背景、按钮及其真实依赖；战斗、商店和篝火资源分别在实际使用时缓存，临时依赖也只恢复确实冲突的分组，避免第一次点击角色时复制整套素材并重载全部本地化。
- 在卡牌总览中切换当前角色或颜色的卡牌皮肤；角色、无色、远古以及“其他”（事件、衍生、状态、诅咒、任务）分类分别保存，并可只显示确实拥有皮肤的卡牌。
- 放大任意卡牌后，可在卡牌顶部为这一张卡单独选择卡图 Mod、切回原版，或继续跟随所属分类；卡框、遮罩、材质和 Ancient 布局由管理器直接读取提供者 PCK 中的声明式配置并应用，不执行提供者代码。
- 与“卡牌管理器”分层共存：玩家在卡牌管理器里明确设置过的卡图/GIF、卡框或文字层由它优先呈现，未设置的层仍由本 Mod 的所选皮肤负责。卡牌管理器导出的独立 Mod 可按清单精确识别静态卡图、卡框与 Ancient 布局；GIF 导出目前使用其静态备用帧，随机卡图、文字格式和字体导出的独立接管留待后续完善。
- 与“异画库”这类完整卡牌呈现系统分层共存：启用异画时，其卡图、无文字画框与文字布局保留最终显示权；它们仅提供功能而没有可选皮肤资源时，不会被误识别成皮肤 Mod 或被隔离自动刷新补丁。
- 卡图包中与玩法基线完全相同的重复资源会被忽略；完整类型名、`generated/assets/card_art` 及提供者私有目录下的散装卡图均会按实际 ModelDb 卡名归类。同一 Mod 内真正不同的子目录变体会拆成独立选项；约定俗成的 `beta` 目录作为同一卡牌备用图处理，不单独伪装成皮肤。未覆盖的卡牌自动从隔离基线加载。
- 在怪物图鉴切换当前怪物的皮肤，并为每个“怪物 + 皮肤”独立调整 50%–200% 的显示大小；图鉴和实际战斗共用设置。
- 在怪物图鉴右侧的小入口打开远古图鉴，并切换当前远古者的皮肤。
- 选择后立即生成并挂载资源覆盖包，无需重启游戏。
- 测试版战斗中的出牌队列会在网络模型重绑定后再次校正逐卡卡图，节点池复用不会沿用上一张牌的实例贴图。
- 被识别为皮肤提供者后，其 DLL 初始化器和全局补丁不会执行，卡牌呈现补丁也不会反射加载或重放。管理器只读扫描 DLL 元数据以识别卡牌布局意图，并按当前分组从 PCK 读取场景、骨骼、贴图、声明式卡牌呈现配置及资源依赖，避免未选中皮肤强制占用或跨分组串皮。
- 支持代码型皮肤常用的 `res://<ModId>/<游戏资源路径>` 私有目录结构；只有实际选中该皮肤时才加载它所需的私有依赖并注册 Godot 场景脚本类型，不运行提供者初始化器。对于依赖 DLL 转换战斗动作的角色骨骼，管理器按通用动画命名约定补充攻击、受击、死亡、施法和待机路由。
- 选择保存在游戏用户目录的 `skin_changer.json` 中，下次启动自动应用；旧版配置会自动迁移。
- 不改写任何已安装 Mod 的 PCK。

## 使用

将发布目录放到游戏的 `mods/SkinChanger` 下并正常启用。角色皮肤选项会出现在选角界面；卡牌皮肤选项和“仅显示有皮肤的卡牌”筛选会出现在卡牌总览“多人模式卡牌”选项上方，并跟随当前选中的角色或颜色卡池；放大卡牌后，顶部会出现只影响当前卡牌的选择器；怪物皮肤选项会出现在怪物图鉴；远古图鉴与角色数据位于图鉴底部的同一级入口。没有对应皮肤时不会显示切换控件。

仅替换皮肤资源、并正确声明 `affects_gameplay=false` 的 Mod 才会作为候选项出现。DLL 外观 Mod 会根据它随附的模板资源、启用配置、远古图片目录或实际 Harmony 视觉补丁目标加入相应选项；只是引用卡牌资源 API 的功能库不会因此被误判。对于不含独立卡牌选择的整包 DLL 皮肤，管理器会在选中期间隔离挂载完整 PCK 并临时启用原作者的视觉初始化器与行为补丁，切换离开后精确卸载该程序集的补丁；这样可保留逐帧动画、充能球、特效、商店与篝火等无法仅靠贴图表达的内容。若同一个完整包同时拥有角色、召唤物或多个怪物，这些对象会作为不可拆分的联动皮肤一起切换、一起回退，并在退出时恢复整包曾覆盖的公共资源。含独立卡牌选择的多分类 Mod 仍按资源逐项隔离，避免一次选择强制影响其他分类。管理器解析 PCK 中的卡图与 `frame_replacements.json` 等呈现数据，并以只读方式扫描 DLL 的 IL 元数据来恢复普通卡转先古布局这类呈现意图。PCK 卡图会识别标准目录和 Mod 自定义的卡图目录，并按卡牌总览的实际筛选规则归类。一个 Mod 若同时影响角色色与远古/其他卡牌，会出现在对应的多个分类中。混合玩法内容和独立视觉功能库会作为当前基础功能保留，不会被误判为皮肤。

## 构建

项目引用本机游戏目录中的 `GodotSharp.dll`、`0Harmony.dll` 和 `sts2.dll`：

```bash
dotnet build STS2SkinChanger/STS2SkinChanger.csproj -c Release
```

也可用 `-p:GameAssemblyDir=<游戏程序集目录>` 指定要验证的游戏版本；不同版本的反编译结果统一存放在 `D:/Projects/Godot/Slay The Spire 2/<版本号>/`。

产物位于 `STS2SkinChanger/bin/Release/Gurio.SkinChanger.dll`；游戏要求 DLL 文件名与 Mod ID 完全一致。

## 开发检查工具

- `tools/PckInspect`：检查 PCK 目录或复制少量文件验证写入器。
- `tools/CatalogInspect`：用实际游戏与 Mod PCK 构建皮肤目录，输出识别结果。
