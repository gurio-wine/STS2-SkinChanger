# 皮肤切换器-Skin Changer

一个独立的《杀戮尖塔 2》皮肤管理 Mod。它不改写其他 Mod 的安装文件，也不依赖旧版“皮肤管理器”。

当前同时兼容正式版 `v0.107.1` 与公开测试版 `v0.111.0`；发布 DLL 以最低支持版本 `v0.107.1` 构建，并采用 `AnyCPU`，供 Windows x64 与 macOS Apple Silicon ARM64 共用。

[Steam 创意工坊 / Steam Workshop](https://steamcommunity.com/sharedfiles/filedetails/?id=3787302680)

## 功能

- 自动识别已加载、且 `affects_gameplay=false` 的纯外观 PCK，以及通过 DLL 接管原场景的外观 Mod。
- 按角色、先古之民以及怪物分别归类皮肤。
- 每一组都可切回游戏原版或当前玩法 Mod 提供的基础外观。
- 在选角界面切换、合并当前角色的皮肤；两个按钮左侧的拖动柄可自由调整位置并自动保存，右键拖动柄可恢复默认位置。右键暂停菜单的“外观”按钮可隐藏它，右键“继续游戏”可重新显示。
- 游戏内暂停菜单新增“外观”：进入后先直接点击画面中的角色、怪物、先古之民、同伴或商人，再打开不会遮住所选目标的设置面板；顶部选择提示只列出当前可见、可选择的目标类型。地图界面也可直接点击 Boss 大图标切换该 Boss 的皮肤。商店房间中的玩家专用立绘可以切换角色皮肤，并单独调整和保存商店姿态的缩放、位移；商人作为独立外观组只提供皮肤切换，并同步刷新本体、手部及所选皮肤的场景行为。目标设置中返回会回到选择状态，再次返回才会回到游戏。
- 角色、怪物和同伴均可按“对象 + 皮肤”分别保存 20%–500% 实战模型缩放及水平/垂直位移；血条、名称与能力图标拥有独立的缩放和位移，并可分别选择是否跟随模型缩放、是否跟随模型移动。怪物的意图也可独立缩放、移动并设置两项跟随规则。模型、血条和怪物意图都可直接拖动并分别重置；先古之民在局内可直接热切换当前场景皮肤。若卡牌或战斗动作仍在结算，生物皮肤会等当前动作安全结束后自动应用，避免在动画中途替换骨骼。
- 整套角色皮肤所包含的宠物/伴随角色会一并热重载，左上角头像与地图角色标记也会刷新；奥斯提等同伴不再提供容易产生冲突的独立皮肤选择，而是跟随所属角色的整套皮肤，同时保留自己单独保存的模型与血条位置。
- 多人游戏会按玩家分别同步角色皮肤，不改写本机保存设置。“发送皮肤改变”和“接收皮肤改变”分别控制两个方向，默认均开启；任意一项均可独立关闭。发送内容包括自己的皮肤、头像与局内缩放/位移，接收仅应用本机同样安装的皮肤。本机缺少时使用本机外观，并允许在局内“外观”中为该远端玩家选择本机已有的替代皮肤。本 Mod 不下载、缓存或动态载入远端皮肤资源，也不会为皮肤准备阻塞开局。
- 选角界面严格按需打包当前预览的背景、按钮及其真实依赖；“沿用游戏场景但替换导入骨骼/贴图”的皮肤会把所需的基线桥接资源与当前骨骼、图集一起重写到本次切换的私有路径，不再污染其他角色的公共资源。战斗、商店和篝火资源分别在实际使用时缓存，临时依赖也只恢复确实冲突的分组。
- 同一游戏会话内会缓存已经合并过的本地化状态；在带有角色名称或说明翻译的皮肤之间来回切换时，不再反复扫描和合并全部 Mod 的语言文件。
- 在卡牌总览中切换当前角色或颜色的卡牌皮肤；角色、无色、先古以及“其他”（事件、衍生、状态、诅咒、任务）分类分别保存，并可只显示确实拥有皮肤的卡牌。
- 放大任意卡牌后，可在卡牌顶部为这一张卡单独选择卡图 Mod、切回原版，或继续跟随所属分类；卡框、遮罩、材质和 Ancient 布局由管理器直接读取提供者 PCK 中的声明式配置并应用，不执行提供者代码。
- 与“卡牌管理器”分层共存：玩家在卡牌管理器里明确设置过的卡图/GIF、卡框或文字层由它优先呈现，未设置的层仍由本 Mod 的所选皮肤负责。卡牌管理器导出的独立 Mod 可按清单精确识别静态卡图、卡框与 Ancient 布局；GIF 导出目前使用其静态备用帧，随机卡图、文字格式和字体导出的独立接管留待后续完善。
- 与“异画库”这类完整卡牌呈现系统分层共存：启用异画时，其卡图、无文字画框与文字布局保留最终显示权；它们仅提供功能而没有可选皮肤资源时，不会被误识别成皮肤 Mod 或被隔离自动刷新补丁。
- 卡图包中与玩法基线完全相同的重复资源会被忽略；完整类型名、`generated/assets/card_art` 及提供者私有目录下的散装卡图均会按实际 ModelDb 卡名归类。同一 Mod 内真正不同的子目录变体会拆成独立选项；约定俗成的 `beta` 目录作为同一卡牌备用图处理，不单独伪装成皮肤。未覆盖的卡牌自动从隔离基线加载。
- 在怪物图鉴切换当前怪物的皮肤，并按地区保存、切换怪物皮肤预设；可为每个“怪物 + 皮肤”独立调整 20%–500% 的模型大小，图鉴和实际战斗共用模型缩放，局内“外观”菜单还可单独调整怪物位置和血条，并决定血条是否跟随模型。
- 怪物整包皮肤附带的地区背景、地图音乐和战斗 BGM 由当前地区“皮肤优先级”统一协调；进入战斗后只会采用本场实际选中怪物皮肤中优先级最高的环境来源。通过局内“外观”或怪物图鉴切换怪物、调整地区优先级时，会同时热重载当前怪物、名称、战斗背景、环境音和当前遭遇的战斗 BGM，不会误切回地区地图音乐。Boss 地图大图标、顶部头像和悬浮名称仍跟随对应 Boss 自己选择的皮肤，并可在局内怪物图鉴或地图“外观”中切换后热刷新。
- 在怪物图鉴右侧的小入口打开“其它图鉴”；其中按“先古”“商人”“生物”分类，先古场景、商人/假商人和异鸟宝宝都可预览并切换皮肤。
- Mod 界面会跟随游戏语言，覆盖英文、简体中文、繁体中文、德语、拉丁美洲西班牙语、法语、意大利语、日语、韩语、波兰语、巴西葡萄牙语、俄语、西班牙语、泰语和土耳其语。
- 选择后立即生成并挂载资源覆盖包，无需重启游戏。
- 测试版战斗中的出牌队列会在网络模型重绑定后再次校正逐卡卡图，节点池复用不会沿用上一张牌的实例贴图。
- 被识别为皮肤提供者后，未选中的 DLL 初始化器和全局补丁不会执行，卡牌呈现补丁也不会反射加载或重放；完整外观包被选中时，只临时启用它自己的动画、场景和特效行为。管理器只读扫描 DLL 元数据以识别卡牌布局意图，并按当前分组从 PCK 读取场景、骨骼、贴图、声明式卡牌呈现配置及资源依赖，避免未选中皮肤强制占用或跨分组串皮。
- DLL 皮肤行为会按当前画面收窄：选角、怪物图鉴和其它图鉴只保留当前预览对象；对局中保留玩家角色、当前战斗可见怪物，以及确实负责整局背景、音乐或特效的怪物提供者；商店与先古场景只在进入对应场景时激活。离场后会停用 Harmony 回调，并暂停提供者遗留的全局处理节点。当前皮肤的小型资源包会单线程后台预读一次，超过 64 MiB 的 CZN 等大型包不会整包预读，避免抢占游戏帧时间和磁盘带宽。
- 支持代码型皮肤常用的 `res://<ModId>/<游戏资源路径>` 私有目录结构；只有实际选中该皮肤时才加载它所需的私有依赖并注册 Godot 场景脚本类型。完整外观包选中时会临时运行其视觉初始化器，切走后卸载行为补丁；纯资源包仍不运行提供者初始化器。对于依赖 DLL 转换战斗动作的角色骨骼，管理器按通用动画命名约定补充攻击、受击、死亡、施法和待机路由。
- 选角界面新增可拖动的“管理皮肤包”按钮，仅管理当前角色的皮肤包：选择一个角色皮肤（含合并皮肤），并为每个卡牌分类、怪物地区分别选择预设。默认勾选“在皮肤列表中隐藏选中的皮肤”，仅隐藏来源条目，包内仍可重新选取；取消勾选或删除该包后，未被其它包/合并皮肤隐藏的来源重新显示。原皮入口始终保留。
- 每个包拥有各分类独立的全原皮预设，默认选用自己的预设，也可改选其它预设；不再提供“不修改”，旧的空引用、失效引用及被删除的预设均回退本包预设，不覆盖有效的其它预设选择或已覆盖的包预设内容。包预设以黄色名称置顶，显示名为“角色名-皮肤包名”，可应用、覆盖内容，不能单独重命名或删除；删除包时一并移除其专属预设。不同角色的同名包以独立 ID 保存，不会串用。
- 皮肤包管理仅显示有可用皮肤的卡牌分类和怪物地区；暂时不可用分类的已保存内容保留，但不参与本次对局应用。参照皮肤合并布局，仅分类列表滚动，名称、角色皮肤、隐藏开关和操作按钮保持固定，不显示底部说明。
- 保存后，[P] 皮肤包会以黄色文字置顶显示在角色皮肤列表；选中时立即切换角色皮肤，点击开始后仅为本局临时应用卡牌和怪物预设，结束或退出本局时恢复原预设。编辑名称后保存即可重命名，删除需再次确认。皮肤包引用预设的最新内容，普通预设改名会同步更新引用，删除后对应项回退本包预设。缺少角色皮肤时使用原皮，应用失败会恢复原设置。
- 旧整套卡牌预设只拆分实际保存了优先级或卡牌选择的分类，不再用当前配置为其它分类补出预设。兼容修复会一次性识别旧迁移留下的同分类、不同原名、完全相同内容的批量副本；单卡覆盖、内容不同、被皮肤包引用或来源不明的条目保留。识别出的副本从列表移至配置中的 `ArchivedLegacyCardSkinPresets`，完整内容可恢复，只移除其启用标记，不重置当前卡面与优先级。旧版未记录来源，因此不能无损推断所有历史条目的创建意图；疑似项不会仅凭名称删除。
- 选择保存在游戏用户目录的 `skin_changer.json` 中，下次启动自动应用；旧版配置会自动迁移。
- 不改写任何已安装 Mod 的 PCK。
- 原皮肤设置与皮肤选择分工协作：SC 管来源和作用对象，作者配置仍保留在原配置文件。当前已接入 Merchant2CuteII 的 `merchant point/voice/foul/status` 命令和原 Mod 详情页设置按钮；首次选用或打开该 Mod 详情后注册，切走后仍可保存设置，但手脚刷新只作用于采用该皮肤的真/假商人（含图鉴）。命令类静态初始化和延迟重试的全场景入口在加载进内存前改为定向刷新，不修改原 DLL/PCK、不重建模型或交易状态。角色皮肤另有按能力识别的行为归属检查：已接管 DLL 同时声明角色类型、皮肤资源与适用性判断时，在作者原判断之后核对当前皮肤来源，Player 调用按对应玩家选择处理，切走后到达的回调重新检查。已核对 CZN 角色实包使用此合同；独立 CZN UI、设置保存、作者开关继续由原代码管理。不按 Mod 名称匹配，也不强制打开作者关闭的功能。未经过这些入口的任意全局写入、无法确认实际提供者的共享管理器回调，仍需核验，不能视为已自动隔离。

## 使用

将发布目录放到游戏的 `mods/SkinChanger` 下并正常启用。角色皮肤选项会出现在选角界面；进入一局游戏后，可从暂停菜单打开“外观”，先点击画面中的角色、怪物、先古之民、同伴或商人，再切换皮肤和调整对应对象。异鸟宝宝等独立生物只提供皮肤和模型设置，不会显示血条、意图等无关选项。角色、怪物和同伴的模型及血条都能直接拖动，怪物意图也能直接拖动；设置面板会自动放到目标另一侧。奥斯提的皮肤跟随亡灵契约师，因此它的局内菜单只提供模型和血条调整。多人游戏中，双方都安装 Skin Changer 时会同步各自选择的角色皮肤；对方选角色、在选角界面或对局中切皮肤后都会立即刷新。本机有同一皮肤时只应用到对应玩家及其同伴，本机缺少时先使用原皮且不会下载，并可在局内只为该远端玩家选择本机已有的替代皮肤。选角界面的“发送皮肤改变”和“接收皮肤改变”默认均开启，分别控制两个方向，可独立关闭。远程选择不会改写本地全局设置。卡牌总览“多人模式卡牌”选项上方提供当前角色或颜色卡池的皮肤优先级，可以同时启用多个 Mod：上方优先，对每张卡牌只应用提供该牌的一个 Mod 的完整效果，较低项只补充未覆盖的卡牌；每个 Mod 也能单独禁止作用于当前分类。卡牌右下角会显示可用来源的颜色标签，当前来源标签会更长，并可筛选有皮肤的卡牌；放大卡牌后，顶部仍有只影响当前卡牌的选择器。怪物皮肤选项会出现在怪物图鉴；通过怪物图鉴入口右上角的“切换”按钮可进入“其它图鉴”，内部提供先古、商人（含假商人）和生物分类。没有对应皮肤时不会显示切换控件。

仅替换皮肤资源、并正确声明 `affects_gameplay=false` 的 Mod 才会作为候选项出现。DLL 外观 Mod 会根据它随附的模板资源、启用配置、先古图片目录或实际 Harmony 视觉补丁目标加入相应选项；只是引用卡牌资源 API 的功能库不会因此被误判。对于整包 DLL 皮肤，管理器会在选中期间隔离挂载完整 PCK 并临时启用原作者的视觉初始化器与行为补丁，切换离开后精确卸载该程序集的补丁；这样可保留逐帧动画、选角语音、卡牌悬浮立绘、充能球、特效、商店与篝火等无法仅靠贴图表达的内容。即使角色皮肤同时附带卡图，卡图资源仍由本 Mod 按分类和单卡选择独立管理，不会因此关闭角色所需的行为层。若同一个完整包同时拥有角色、召唤物或多个怪物，这些对象会作为不可拆分的联动皮肤一起切换、一起回退，并在退出时恢复整包曾覆盖的公共资源。含独立卡牌选择的多分类 Mod 仍按资源逐项隔离，避免一次选择强制影响其他分类。管理器解析 PCK 中的卡图、`frame_replacements.json` 等呈现数据和提供者自己的卡图启用配置，并以只读方式扫描 DLL 的 IL 元数据，恢复先古卡图、整卡框美化和普通卡转先古布局这类呈现意图。PCK 卡图会识别标准目录和 Mod 自定义的卡图目录，并按卡牌总览的实际筛选规则归类。一个 Mod 若同时影响角色色与先古/其他卡牌，会出现在对应的多个分类中。混合玩法内容和独立视觉功能库会作为当前基础功能保留，不会被误判为皮肤。

## 原皮肤管理器协作

皮肤管理器属于功能 Mod，不因参与加载顺序检查就标记 `[SC]`，被接管的皮肤内容仍标记。`thunninoi's Skin Loader and Manager` 已启用时，由游戏加载原管理器，SC 不抢先加载同名接口 DLL，也不卸载它的整套显示补丁。它自己的控件、预览、作者设置、注册表、缓存和 `thunni_skin_info.json` 读写保留。

双方的显式切肤请求使用同一热切换事务，后一次选择可替换仍在预读的前一次选择；成功应用后通过原生接口同步本机选择，避免反复互相覆盖。原控件在资源准备完成后刷新；原管理器对选角大图、角色按钮和联机头像的直接刷新仅限其自己的皮肤，外部皮肤由 SC 更新，但小模型预览不受此限制。查询按当前对象/玩家处理，远端显示或临时预览不写入本机管理器的选择文件。框架已原生处理的呈现不再叠加 SC 后备实现；无选择条件的原登场动画补丁则限制到该框架当前皮肤，避免污染其它皮肤。

原管理器的左右箭头使用 SC 当前角色下拉列表的实际可见条目及顺序，包括原皮、其它来源的皮肤、合并皮肤和置顶的 `[P]` 皮肤包；被隐藏的合并素材不会重新出现在循环中。皮肤包仍只立即预览角色皮肤，其它预设在开局时应用。原控件名称和循环位置读取已提交的皮肤包/皮肤状态，连续点击从待加载项继续计算；切出皮肤包后也会重建 SC 列表，避免名称滞留和反向跳项。

小模型预览保留原控件，在其内部使用 SC 同一模型工厂：原皮和受管理场景先从当前选择的隔离资源创建，避免共享缓存中的普通 Node2D 在后处理之前触发强制类型转换；纯运行时皮肤保留原构造流程。预览保留完整模型和子节点，挂载资源覆盖到 Ready 完成，切换时释放旧树而非只复制一个 Visuals 子节点。静态图不调用 Spine，动画模型只播放实际存在的登场/待机动作。离线检查覆盖创建路由和原控件入口，不代替游戏内画面复测。

未加载原管理器时，SC 在选角界面提供自己的模型预览框，默认贴近左侧角色信息框并与其等高、上下对齐；框左侧的黑条高度为框的 80%、垂直居中，透明度与预览背景一致，两侧留相同的小间距。黑条可以左键拖动，松手独立保存位置，右键恢复默认布局。预览不显示皮肤名称或前后切换按钮。它与原管理器共用模型工厂及像素取景，跟随当前角色/皮肤刷新，窗口调整只重新取景；开始游戏或隐藏选角界面时清理模型。真正加载原管理器后不显示 SC 的框，内置兼容接口不算原管理器。

预览使用独立、满血的角色所属节点，补齐所选皮肤的角色级、生物级和节点级外观初始化，不生成卡组/遗物，不加入战斗，也不重放房间回调。完整模型一次性挂入独立透明 SubViewport，几何范围只作为初始相机位置；最终取景读取引擎实际渲染的可见像素，不区分骨骼、图片、序列帧等格式，不再临时拆除骨骼附件或写入固定皮肤倍率。

取景在 FramePostDraw 后进行，正常两次非裁切有效测量后停止，最多六次；碰到画布边缘先拉远，空帧不清空相机。相机最终调整再渲染一帧后展示，随后停止像素回读；视口最长边限制 1024 像素，图像每次读完立即释放。隐藏控件时禁用该视口渲染和处理，切走/退出时取消测量并解除回调。原播放按钮会等取景完成后再播放登场动画，不在动作过程中反复自动缩放。真正画出来的宽大武器、翅膀或背景仍会参与取景，无法取得像素时保留粗相机并记录日志；最终显示仍需游戏内核验。

选角呈现和节点 Ready 的恢复快照排除 Spine 自行创建的 `SpineMesh2D` 子树。换骨骼会重建这些网格，但它们不是作者新增的外观节点；只能由所属 SpineSprite 管理销毁，否则切走皮肤后渲染器仍引用已删除网格，会原生闪退。作者新增的整个模型及普通附件仍正常跟踪、恢复。

按角色返回战斗骨骼路径的运行时皮肤，小预览读取当前选中提供者的完整骨骼并隔离其图集依赖，不在菜单里执行战斗初始化。预览适配原控件背景框并避开名称/箭头，只调整独立预览相机，不改变选角大图、战斗模型或玩家保存的缩放，也不改写原管理器或皮肤 Mod 的文件。识别纯运行时皮肤时，通用工具表里出现的角色名字不算适用对象；需要明确目标字段或角色到皮肤路径的分发方法。

卡框/轨迹、能量、多人手势、充能球等声明资源遵守已识别的作者开关，并将开关状态纳入资源缓存键。不同管理器可使用不同的窄接口桥；这不是自动兼容所有未知管理器的保证。CZN 等已有的作用域/设置协作继续保留。

原管理器未安装或未启用时，仍使用随 SC 提供的行为隔离接口，支持已核验、资源完整的皮肤；这种后备模式不提供原管理器的设置界面。启用原管理器则必须满足它自己的 BaseLib 等依赖，不绕过游戏的依赖检查。不覆盖原管理器、皮肤 Mod 或玩家的作者配置文件。

原管理器使用旧游戏动画接口时，在游戏正常请求加载其 DLL 的时机复用跨版本接口桥，仅调整内存中的接口调用，保留原 CLR 身份、初始化器、功能补丁、PCK 加载及原目录信息。不会抢先执行初始化，也不会写回原 DLL。正式版接口未发生变化时继续原样加载；当前实包在测试版需要桥接 5 处动画调用。

## 构建

需要 **.NET 9 SDK**（只有运行时不能编译）。`global.json` 将工具链限定为稳定版 .NET 9；当前开发主环境为 Windows 原生 PowerShell。

从 WSL 迁移现有仓库时，建议执行 `git config --local core.longpaths true`。Codex 的历史检查点引用可能具有很长的路径；开启后 Windows Git 才能完整读取这些引用，无需删除历史检查点。

项目通过 `Directory.Build.props` 引用本机游戏目录中的 `GodotSharp.dll`、`0Harmony.dll`、`Steamworks.NET.dll` 和 `sts2.dll`，默认使用最低支持的正式版 `v0.107.1`：

```powershell
dotnet build STS2SkinChanger/STS2SkinChanger.csproj -c Release
```

Windows 默认游戏程序集目录为 `D:/Programs/Steam/steamapps/content/app_2868840/depot_2868841/data_sts2_windows_x86_64`；WSL 自动使用对应的 `/mnt/d/...` 路径。其它安装位置通过 `-p:GameAssemblyDir=<游戏程序集目录>` 指定。

测试版必须显式指定引用，并使用独立的 `ReleaseBeta` 配置，避免把测试版验证产物误当成正式版兼容发布包：

```powershell
dotnet build STS2SkinChanger/STS2SkinChanger.csproj -c ReleaseBeta -p:Optimize=true "-p:GameAssemblyDir=D:/Programs/Steam/steamapps/common/Slay the Spire 2/data_sts2_windows_x86_64"
```

Windows 与 WSL 的还原和中间文件分别写入 `obj/windows`、`obj/unix`，不会沿用旧系统的 NuGet 绝对路径。旧 `obj` 目录无需复制或手工改路径，也不会作为源代码参加编译。不要同时从两个系统构建到同一个输出目录。

不同版本的反编译结果统一存放在 `D:/Projects/Godot/Slay The Spire 2/<版本号>/`。

发布产物位于 `STS2SkinChanger/bin/Release/Gurio.SkinChanger.dll`，测试版验证产物位于 `STS2SkinChanger/bin/ReleaseBeta/`；游戏要求 DLL 文件名与 Mod ID 完全一致。发布 DLL 保持 `AnyCPU`，不因开发环境迁移到 Windows 而限制为 x64。

## 开发检查工具

- `tools/PckInspect`：检查 PCK 目录或复制少量文件验证写入器。
- `tools/CatalogInspect`：用实际游戏与 Mod PCK 构建皮肤目录，输出识别结果。
- `tools/Test-BuildEnvironment.ps1`：通过真实 MSBuild 求值检查五个项目的正式版默认引用、测试版覆盖、跨系统缓存隔离及 AnyCPU，需 PowerShell 7。
- 运行时测试附加 `-- --audit-provider-animation <皮肤DLL路径>`：对实包进行跨版本动画接口桥接和 JIT 检查，不执行提供者初始化或游戏画面；正式版与测试版分别运行，不能代替实机换肤验证。
- 运行时测试附加 `-- --audit-slot-toggle <渡鸦疫医DLL路径>`：检查实包的交互显隐脚本，以及选角、战斗、商店角色、休息处骨骼部件映射。部件开关按角色和皮肤保存；同名骨骼部件通用恢复，不同骨骼仅应用已核验的映射。只作用于本机玩家，不会把本机的部件开关套到联机队友；此检查不启动游戏。
- 运行时测试附加 `-- --audit-provider-settings <Merchant2CuteII.dll路径>`：检查实包的旧式设置入口内存改写和原配置/命令合同；`-- --audit-preserved-settings <CznStyleUI.dll路径>` 确认其它设置系统不会被此适配器修改。两者不运行皮肤初始化器、不写玩家配置、不启动游戏，不能代替实际设置切换验证。
- 运行时测试附加 `-- --audit-skin-behavior <角色皮肤DLL路径>`：仅检查实包是否具有可接入的角色皮肤适用性合同，不执行初始化器。常规 RuntimeTests 另验证真实注册/选择服务、作者关闭选项、切走后延迟调用、同角色双玩家以及异常后的作用域恢复。
- `dotnet run --project tests/STS2SkinChanger.FrameworkTests -c Release -- <原管理器DLL绝对路径>`：独立进程加载原 DLL，验证原生状态/缓存/保存流程、防回声、玩家作用域、配置委托、精确补登记和原功能补丁保留。仅测试引擎 IO/日志边界被替换，不写玩家配置；可同样传入 `ReleaseBeta` 和测试版 `GameAssemblyDir`。不执行原 Mod 初始化器、不启动游戏，不代表界面或局内表现已实机验证。

```powershell
./tools/Test-BuildEnvironment.ps1
dotnet run --project tests/STS2SkinChanger.LogicTests/STS2SkinChanger.LogicTests.csproj -c Release
dotnet run --project tests/STS2SkinChanger.RuntimeTests/STS2SkinChanger.RuntimeTests.csproj -c Release
dotnet run --project tests/STS2SkinChanger.RuntimeTests/STS2SkinChanger.RuntimeTests.csproj -c ReleaseBeta -p:Optimize=true "-p:GameAssemblyDir=D:/Programs/Steam/steamapps/common/Slay the Spire 2/data_sts2_windows_x86_64"
dotnet publish tools/WorkshopPublisher/WorkshopPublisher.csproj -c Release
```

最后一条仅构建上传工具，不会上传工坊。上传和本地部署必须另行执行，并核对正式版兼容产物及各部署目标的版本/哈希。
