# 工坊社区投稿 Implementation Plan

**Goal:** 玩家批量扫描已订阅的本地皮肤并复制多条投稿码；每次启动及手动刷新读取固定投稿帖全部公开页面，校验后合入游戏内工坊。

**Architecture:** 本地扫描、纯数据编解码、固定讨论帖读取、经 Steam 核验的社区清单、现有主题 UI 五部分独立。内置清单优先，社区条目不改变订阅或当前皮肤。网络/分页失败保留完整旧缓存，不以部分结果替换。

**Tech Stack:** C# / .NET 9、Godot、Steamworks.NET、现有皮肤 Catalog，无额外运行依赖。

**Spec:** 本会话用户要求，已明确授权直接实现。直接 master，不启动游戏，不自动发帖，不上传工坊。

## Global Constraints

- 正式版 v0.107.1、测试版 v0.111.0；发布 AnyCPU；四段内测版本，提交后双目录部署。
- UI 复用现有主题、固定头尾及可滚动列表，15 种语言。
- 仅固定 HTTPS Steam 讨论帖；分页与解压有资源上限，格式错误不能执行任何代码。
- 校验工坊物品属于本游戏；标题封面取 Steam，不使用投稿里的任意 URL。

## SCM2 完整性与诊断（1.0.3.4 历史记录；名称规则已撤销）

- 一 Mod 一组；可读名称、工坊 ID、组校验、片号/总片数及单片校验。完整压缩数据分片，不再独立合并同一 Mod 的部分分类；组收齐才产生候选。
- 生成与校验统一查询 Steam `english` 名称；检查所属游戏与名称，作者改名后需要重新投稿。无名称的旧码/缓存不再收录。
- “码错误”独立展示全部诊断，不受当前类型/地区筛选限制：ID、双方名称、错误类型、组号/码指纹、缺片、来源页与回复；可跳转固定原帖、复制原码和诊断，无订阅操作。
- 网络失败保持完整旧快照；坏新码仅可沿用名称仍匹配的历史有效条目，不覆盖内置人工清单。错误随缓存保留，原帖修正后刷新自动消除。
- 新增完整组、名称校验、冲突/损坏/未知版本、跨页原帖定位、错误筛选/报告、链接限制、15 语言与缓存无效结构测试；未启动游戏或发测试帖。
- 最终验证：Release 正式版、ReleaseBeta 测试版全套 RuntimeTests、LogicTests、Test-BuildEnvironment 通过。实际讨论页匿名只读检查通过，目前 0 个完整投稿组、0 个码错误；Steam 登录态名称核验及游戏 UI 待用户实测。
