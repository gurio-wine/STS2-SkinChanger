# 工坊社区投稿 Implementation Plan

**Goal:** 玩家批量扫描已订阅的本地皮肤并复制多条投稿码；每次启动及手动刷新读取固定投稿帖全部公开页面，校验后合入游戏内工坊。

**Architecture:** 本地扫描、纯数据编解码、固定讨论帖读取、经 Steam 核验的社区清单、现有主题 UI 五部分独立。内置清单优先，社区条目不改变订阅或当前皮肤。网络/分页失败保留完整旧缓存，不以部分结果替换。

**Tech Stack:** C# / .NET 9、Godot、Steamworks.NET、现有皮肤 Catalog，无额外运行依赖。

**Spec:** 本会话用户要求，已明确授权直接实现。直接 master，不启动游戏，不自动发帖，不上传工坊。

## Global Constraints

- 正式版 v0.107.1、测试版 v0.111.0；发布 AnyCPU；四段内测版本，提交后双目录部署。
- UI 复用现有主题、固定头尾及可滚动列表，15 种语言。
- 仅固定 HTTPS Steam 讨论帖；分页与解压有资源上限，格式错误不能执行任何代码。
- 校验工坊物品属于本游戏；标题封面取 Steam，不使用投稿里的任意 URL。

## 损坏投稿撤下与统一错误卡片（1.0.3.7）

- 本节取代旧版“坏码回退到上次完整条目”的规则：成功读取完整讨论帖并核验后，只保留本轮有效投稿。删码、截断、缺片或冲突导致该物品已无有效码时撤下社区条目；修复后再次收录。其它独立有效码和人工内置条目不受坏码影响。网络、分页或 Steam 查询整体失败仍保持上次完整快照，不改玩家实际订阅或已安装文件。
- “码错误”复用普通卡片的同一行构建器、8 项/页双列槽池、主题、封面、走马灯、悬停及资料缓存。没有标签/统计/楼层选择器/组号区；左下角显示原因，右侧依次“复制错误”“定位原帖”。原码、组号、片号、全部来源链接仍在复制报告中；定位按钮直接打开首个相关原帖。
- 错误物品资料按 ID 只读查询，封面和名称共用常规加载路径；未知 ID 使用占位，不把内部槽号当作工坊 ID。不将错误 ID 加回订阅清单或放宽订阅/加载权限；错误专属 ID 仅按当前页增量读取。来回切换清理标签、按钮动作、重启高亮并更新绑定代次，拒绝旧页异步回调和旧点击。
- 回归测试覆盖发布有效码→删末位/缺片/全删→修复、重复独立有效码、内置条目、错误缓存恢复、资料 ID 边界、网络失败保留缓存及全部 15 种错误界面文案；不启动游戏，视觉/交互仍由用户实测。
