# 注册式皮肤框架协作

用户已同意修订：管理器是功能 Mod，不整包接管、不移除其全部显示补丁、不标记 [SC]。原 UI、设置、预览、动画继续执行；只协调同一对象上的皮肤选择冲突，最后一次玩家明确选择生效。内置接口仅作无原管理器时的后备。直接在 master 实施，不启动游戏、不自动上传。

## 双路径

- 启用原框架时，不加载同名内置 DLL。原框架经游戏正常检查依赖、版本、DLL/PCK 并初始化，加载后安装协作桥。
- 原框架未启用/未安装时，仅在已有资源闭包证据满足的情况下加载内置兼容接口，保留此前无需订阅前置的用法。
- 原框架已被另一条路径加载或版本不支持协作时，不再塞入第二份同名程序集。失败记录日志，不跳过原框架依赖要求。
- 游戏正常请求加载原宿主时，复用现有动画接口漂移适配器；只适配内存中的接口签名，保留原程序集身份和原 ModDirectory。不同游戏版本不通过屏蔽原功能来规避接口错误。

## 权限分工

- 原框架持有 SkinData、资源声明、RegisterConfig 委托和设置 UI。SC 不复制或改写原 DLL、原配置文件。
- GetActiveSkin/IsUsingSkin/模型附属资源解析按 SC 当前选择范围查询；SetActiveSkin/循环切肤转成 SC 的切肤请求。
- 原框架的 Load/Save 和缓存刷新保留；SC 成功应用本机选择后通过防回声的同步调用更新原注册表。远端/预览作用域仅参与渲染查询，不写原框架的本机保存选择。
- 不卸载原框架的 Harmony 显示补丁，也不由 SC 创建替代控件。原入口创建和预览刷新继续使用原代码；加载未完成或切到非该框架皮肤时，仅暂停会重建当前人物的冲突刷新。
- 原 SkinDbSetup 会清空所有皮肤，finializeSetup 重复 Add 指针。仅对此注册生命周期做幂等保护，晚到的皮肤只重放自己的登记回调，不触发其它提供者。
- SC 的声明式框架资源查询需尊重原注册的功能开关，不能表面保留配置但实际无条件套用卡框、能量、手部、充能球。
- 框架皮肤初始化器仅在原框架协作已生效且存在该框架声明时启用一次，以恢复被原有“跳过初始化器”路径漏掉的 BaseLib 配置注册。其它声明式接管不受影响。

## 验证

单独进程加载原管理器 DLL，防止 RuntimeTests 对内置同名接口的引用污染审计。验证真实注册数据、原生 setter/cache/save 执行、防回声、作者配置、默认回退、重复登记、玩家作用域、两条装载路径和原补丁保留。正式/测试版构建与离线测试；游戏退出后部署 0.10.3.7，核对版本和哈希。不同管理器使用各自已确认的接口桥，不宣称能自动适配任意未知管理器。
