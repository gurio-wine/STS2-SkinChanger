# 角色皮肤包设计

## 目标

在选角界面为当前角色保存和切换一组外观设置。每个皮肤包包含：

- 一个角色皮肤，可为普通皮肤、合并皮肤或原皮；
- 零个或多个卡牌分类预设引用；
- 零个或多个怪物地区预设引用。

未选择预设的分类使用“不修改”，应用皮肤包时保留玩家当时的设置。

## 数据模型

皮肤包保存稳定名称、所属角色组、角色皮肤选项 ID、卡牌分类到预设的引用，以及怪物地区到预设的引用。预设引用使用分类 ID 与预设名称；重命名预设时同步更新引用，删除预设时移除对应引用。

皮肤包引用现有预设，不复制预设内容。覆盖卡牌或怪物预设后，所有引用它的皮肤包自动使用新内容。角色皮肤不可用时应用原皮；个别预设不可用时跳过并向玩家列出未应用项目。

## 界面

选角界面新增可拖动的“皮肤包”按钮，仅显示和编辑当前角色的皮肤包。位置独立保存，拖动柄右键恢复默认位置。

编辑弹窗沿用现有游戏主题，包含：

1. 皮肤包名称；
2. 当前角色的皮肤选择，包括合并皮肤；
3. 每个已有卡牌分类的预设下拉框，首项为“不修改”；
4. 每个已有怪物地区的预设下拉框，首项为“不修改”；
5. 新建、应用、覆盖、重命名、二次确认删除和关闭操作。

## 应用事务

应用前先解析并验证角色皮肤及全部预设引用，然后复制当前角色、卡牌与怪物配置作为回滚快照。有效项目在内存中统一应用，只保存一次配置并刷新一次相关资源。任何应用或保存失败都会恢复完整快照并重新挂载原资源，不能留下半套设置。

“不修改”的分类不参与事务。缺失角色皮肤回退原皮；缺失预设不阻断其他有效项目，但会在结果提示中列出。

## 兼容和迁移

现有配置自动补充空的皮肤包集合、当前皮肤包记录和按钮位置，不改变旧设置。卡牌或怪物预设重命名与删除操作负责同步修正皮肤包引用。

## 验证

- 纯逻辑测试覆盖角色隔离、可选分类、引用重命名/删除和事务回滚。
- 运行时测试覆盖配置往返保存、按钮及补丁目标，并分别针对正式版和测试版程序集运行。
