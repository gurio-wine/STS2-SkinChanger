# 角色皮肤合并设计

日期：2026-09-03

## 背景

角色头像、选角预览、局内模型、名称、语音、特效和附属资源本来都属于一套角色外观。独立提供头像来源会把同一套外观拆成两条选择路径，也会让选角、多人、左上角头像和地图头像产生额外分支。新的方案取消独立头像选择，把纯头像包也视为普通角色皮肤，并允许玩家把当前角色的任意皮肤按优先级组合成一个可保存、可选择的合并皮肤。

## 目标

- 在选角界面左上角为当前角色提供“皮肤合并”入口。
- 同一角色的皮肤可以按玩家指定的顺序组合；前面的来源优先，后面的来源只补充缺失内容，游戏原版最终兜底。
- 允许只选择一套皮肤保存，用作该皮肤的自定义别名。
- 合并结果命名后作为普通皮肤出现在选角和局内角色皮肤列表中，并走现有统一热重载流程。
- 纯头像 Mod 不再拥有独立选择器，也不再被自动注入所有角色皮肤，而是成为可单独选择、可参与合并的普通皮肤。
- 玩家可以选择在普通皮肤列表中隐藏某个合并配置使用的原始皮肤，但这些来源在合并编辑器中始终可见。
- 多人游戏同步合并配方；各客户端仅使用双方都具备的组成皮肤，不下载远端资源。

## 非目标

- 不修改、复制或重打包其他作者的原始 Mod。
- 不允许合并皮肤继续嵌套另一个合并皮肤，避免循环引用与无法预测的优先级。
- 不同时运行多个完整皮肤的 DLL 动态行为。一个角色的一次合并只选择一个动态行为提供者。
- 本功能只处理角色皮肤，不扩展到怪物、先古、商人、卡牌或生物。

## 用户界面

### 入口

- “皮肤合并”按钮固定在选角界面左上角，使用游戏现有按钮主题。
- 按钮仅操作当前选中的角色；未选中角色时隐藏。
- 当前角色只要存在至少一套非原版皮肤就可以使用，不要求至少两套。
- 该入口只出现在选角界面。合并皮肤保存后仍会出现在选角界面和局内“外观”的角色皮肤列表中。

### 编辑弹窗

- 弹窗使用不透明度适中的全屏蒙版和原版风格面板，点击外部不会穿透到底层选角组件。
- 顶部显示当前角色，并允许选择“新建合并”或该角色已有的合并皮肤。
- 中间列出当前角色的全部原始皮肤，包括已从普通列表隐藏的皮肤；不列出其他合并皮肤。
- 每行包含启用框和上下移动按钮。启用项按从上到下的顺序形成优先级。
- 下方提供名称输入框和“在皮肤列表隐藏参与合并的皮肤”复选框。
- 操作按钮为“保存”“删除”“关闭”。删除按钮只在编辑已有配置时显示。
- 至少选择一个原始皮肤才能保存。只选一项是受支持的正常用法。
- 空名称自动生成“合并皮肤 1”；名称重复时自动追加连续数字，不阻止玩家保存。
- 保存后立即选择该合并皮肤并刷新当前角色预览。编辑当前正在使用的合并皮肤后，也立即完整热重载。
- 删除正在使用的合并皮肤时安全切回游戏原皮；删除或取消隐藏后，原始皮肤立即重新出现在列表中。

## 配置模型

在现有 `skin_changer.json` 中新增按角色保存的合并配置。每项包含：

- 稳定且与显示名称无关的配置 ID；
- 角色分组 ID；
- 玩家设置的显示名称；
- 按优先级排列的原始皮肤选项 ID；
- 是否隐藏参与合并的原始皮肤。

现有 `Selections` 继续保存当前角色选择，只是允许其值指向合并配置 ID。改名不改变 ID，因此不会使已有选择失效。合并配置引用的皮肤被卸载时不删除该引用；解析时跳过缺失来源，重新安装后自动恢复。

同一个原始皮肤只要参与任意一个启用了隐藏的合并配置，就从该角色的普通皮肤列表隐藏。隐藏仅影响列表展示，不影响目录识别、资源加载、已有选择或合并编辑器。

## 独立头像迁移

- 移除选角界面的头像文字、头像来源下拉框以及新的独立头像写入路径。
- 纯头像包在目录中生成普通 `SkinOption`，选择它时使用游戏原版补齐模型等缺失资源。
- 旧配置若为“跟随角色皮肤”或“游戏原版头像”，直接清除过时字段，不改变当前角色皮肤。
- 旧配置若明确选择了头像 Mod，则首次迁移时建立一个合并配置：头像皮肤排在当前角色皮肤之前；当前角色为原皮时只包含头像皮肤。迁移后选择该合并配置，从而保留玩家原来的视觉结果。
- 迁移生成的配置默认不隐藏来源，并按参与皮肤名称自动命名；发生重名时使用相同的连续数字规则。

## 合并解析

### 统一选择模型

普通皮肤在运行时也被视为只有一个来源的皮肤栈。选角预览、局内外观、角色名称、头像、地图标记、商店姿态、篝火姿态和多人角色不再分别判断“普通皮肤”或“合并皮肤”，而是统一取得一个已解析的角色外观选择。

解析结果包含：

- 有序且当前可用的来源选项；
- 每个规范资源目标最终采用的资源及其来源；
- 唯一的动态行为提供者；
- 需要恢复基线的全部提供者和资源路径；
- 用于缓存和多人同步的稳定签名。

### 资源优先级

- 按配方从前到后遍历来源。
- 使用目录现有的规范目标路径和语义绑定判断两个素材是否作用于同一个目标，不能只比较提供者私有目录中的文件名。
- 模型、场景、骨骼、贴图、头像、选角按钮、地图标记、名称、描述、语音、特效、遗物图及其他已被角色皮肤目录识别的资源均使用先到先得规则。
- 名称、描述等本地化内容按角色条目和字段合并，前面的来源只占用自己明确提供的字段，后面的来源仍可补充其他字段。
- 一个获胜资源的图集、导入文件、骨骼贴图和场景依赖必须与该资源来自同一个提供者，不能从不同皮肤拼接依赖。
- 所有来源都未提供的目标使用游戏原版或当前玩法角色的基础资源。

### 动态行为

- 从前到后选择第一个需要 DLL 初始化器、Harmony 视觉补丁、动态场景控制器或特效控制器的来源，作为唯一动态行为提供者。
- 其余来源仍可提供静态 PCK 资源，但不执行其 DLL 初始化器和运行时补丁。
- 动态提供者自身必需的私有脚本和场景依赖仍会注册、挂载；最终规范资源覆盖仍服从合并优先级。
- 从合并皮肤切走时，先停用动态提供者，再恢复所有参与来源可能污染的规范资源，最后应用新选择，避免残留骨骼、附件或特效。

## 运行时集成

- 目录保留所有原始 `SkinOption`，并根据配置生成可解析的虚拟合并选项；原始选项不会被修改或复制。
- 皮肤列表通过统一的“当前角色可见选项”接口取得数据，以便应用隐藏规则；内部资源解析仍能访问隐藏来源。
- `ApplySelection`、预览选择、局内选择和多人选择都先解析为同一种角色外观结果，再执行覆盖挂载与刷新。
- 覆盖顺序为：恢复全部相关基线、准备获胜资源及依赖、挂载唯一动态提供者所需包、写入最终合并覆盖、刷新角色节点及所有衍生 UI。
- 热重载刷新范围包含大预览、角色模型、角色名称和描述、选角按钮、多人头像、局内左上角头像、地图角色标记、商店与篝火姿态、随角色皮肤绑定的同伴及所选动态提供者的动画和特效。
- 编辑未被使用的配方只刷新皮肤列表；编辑当前配方才重新挂载资源。

## 多人同步

- 联机消息传输角色分组、合并配置的稳定会话 ID，以及有序的原始皮肤来源身份；不要求对方本地存在同名合并配置。
- 接收端按顺序保留本机也安装并识别到的来源，跳过缺失来源，再按相同合并规则生成仅属于该远端玩家的临时解析结果。
- 若没有任何共同来源，该玩家使用游戏原皮；不会下载、缓存或动态安装远端皮肤。
- 远端玩家拥有部分来源时允许部分合并，因此双方最终看到的外观可能不同。
- 动态行为仍只取接收端可用来源中优先级最高的一项。
- 远端合并选择与本机全局角色选择严格隔离；收到配方或顺序变化后立即刷新对应玩家的选角头像和模型，进入对局后继续按玩家隔离。
- 本功能需要提升 Skin Changer 联机协议版本；旧协议玩家按现有能力检测安全回退为原皮，不阻塞开局。

## 性能与缓存

- 解析缓存键由角色分组、配置 ID、配置内容版本和当前目录指纹组成。
- 只有保存或删除配方、皮肤安装集合变化、目录重建时才使相关角色缓存失效。
- 选择和热重载只构建当前角色需要的合并覆盖，不扫描或重挂其他角色。
- 已解析的规范资源所有权和依赖集合直接复用于大预览、头像和局内实例，避免每个入口重复遍历全部 Mod。
- 不生成永久 PCK，也不复制第三方 Mod；继续使用现有临时覆盖包生命周期和大型提供者按需挂载策略。

## 失败处理

- 保存配置、解析资源、挂载覆盖和刷新节点作为一次事务处理。
- 新合并选择失败时恢复原选择、原覆盖、原动态提供者和原配置，并显示具体失败来源；不得留下半套皮肤。
- 某个来源已卸载或当前版本无法识别时只跳过该来源，并在编辑器中标记为不可用，不删除玩家配置。
- 配置 ID 不合法、来源重复或旧数据损坏时进行去重和清理；清理后为空的配方保留在编辑器中等待修复，但不能被应用。
- 隐藏状态不会阻止回滚、删除或重新选择其原始来源。

## 本地化

新增的按钮、弹窗标题、来源状态、隐藏说明、默认名称、保存、删除、关闭和错误提示全部加入现有15种游戏语言。数字优先级和玩家自定义名称不翻译。

## 验证

### 自动测试

- 单来源别名与多来源顺序稳定性；
- 同一规范目标前项获胜、后项补缺和原版兜底；
- 获胜资源与其依赖保持同一来源；
- 多个代码型皮肤只选择首个动态行为提供者；
- 纯头像包成为普通皮肤且不再自动注入其他皮肤；
- 隐藏、取消隐藏、删除和多配方共同隐藏同一来源；
- 旧头像配置迁移且视觉顺序保持一致；
- 缺失 Mod 被跳过、重新安装后恢复；
- 配方改名不改变选择 ID；
- 多人完整匹配、部分匹配、完全缺失、旧协议回退及逐玩家隔离；
- 编辑当前配方失败时事务回滚。

### 构建与实机

- 正式版和公开测试版程序集分别构建，运行现有逻辑测试、目录导出自检和运行期补丁目标测试。
- 实机检查至少覆盖：纯头像包加完整角色皮肤、两套静态皮肤、两套代码型皮肤、单来源别名、隐藏来源、改名、删除、选角热切换、局内热切换、商店/篝火、保存重进和双客户端部分 Mod 缺失。
- 每轮实现提交递增内测小版本并部署本地；只有用户要求上传时才归并正式版本并上传工坊。
